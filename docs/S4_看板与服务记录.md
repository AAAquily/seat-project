# S4 网页看板与服务记录

> 日期：2026-11-05　依赖：S3 的 seat.db 数据与 S2 的 seat_v1 权重

## 一、启动方式

```bash
cd D:\seat-project
D:/miniconda3/envs/seat/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

浏览器打开 <http://127.0.0.1:8000/> 即可看到看板。

## 二、代码结构

| 文件 | 职责 |
|---|---|
| `app/main.py` | FastAPI 路由：状态 / 事件 / 统计 / 立即检测 / 标注图 |
| `app/detector.py` | 模型进程级单例，避免每次请求重复加载权重 |
| `app/db.py` | 新增 `fetch_latest_snapshots`、`fetch_ongoing_violations` 两个看板查询 |
| `app/static/index.html` | 单文件看板页面（原生 HTML/CSS/JS，无外部依赖，离线可用） |
| `config.yaml` | 新增 `demo` 段：看板「立即检测」使用的底图与标注图输出路径 |

## 三、接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查：权重存在性、库内座位数 |
| GET | `/api/seats` | 12 座当前状态（每座最新观测 + 进行中占座事件） |
| GET | `/api/events?limit=20&seat_id=C01` | 占座事件列表 |
| GET | `/api/summary?day=2026-11-05` | 当日各状态帧数与占座次数 |
| POST | `/api/detect` | 用演示底图跑一次检测并落库，返回最新状态 |
| GET | `/api/frame` | 最近一次检测的标注图 |

## 四、看板设计要点

1. **配色语义**：有人=绿、有物无人=橙、占座中=红（脉冲高亮 + 徽标）、空置=灰。
   与判定图不同——看板里红色留给「占座」这个需要人工处理的告警态
2. **座位排序按 ROI 空间位置**（纵向中心分带、横向中心排序），布局接近真实教室排布
3. **5 秒自动轮询**，可暂停；「立即检测」按钮实时跑一次推理（模型已缓存，约 0.3 秒）
4. **占座状态来源**：`occupancy_events` 中 `outcome=ONGOING` 的记录，与状态机的判定闭环一致

## 六、已知边界

1. `/api/detect` 只写观测不推进状态机——占座计时仍由 `track_stream.py` 负责，看板负责展示
2. 页面轮询与检测共用 SQLite，连接按请求创建，无跨线程复用问题
3. 局域网访问需把 `--host` 改为 `0.0.0.0`，并注意防火墙放行 8000 端口

## 七、上传识别功能（v0.2 追加）

看板新增「识别来源」面板，支持两种免采集的验证方式，结果都**不写入数据库**（避免冲掉实时采集的状态）：

### 接口

| 接口 | 说明 |
|---|---|
| `POST /api/analyze/image` | 上传图片（≤25MB）→ 单帧识别，返回 12 座状态 + base64 标注图 |
| `POST /api/analyze/video` | 上传视频（≤300MB）→ 建后台任务逐帧识别，返回 job_id |
| `GET /api/jobs/{id}` | 任务进度 + 实时座位状态 + 状态变化时间线 + 占座事件 |
| `GET /api/jobs/{id}/frame` | 当前处理帧的标注图 |
| `POST /api/jobs/{id}/cancel` | 取消任务 |

### 两个关键参数（上传视频时可选）

- **时间倍率 time_scale**：视频内 1 秒按几秒计入占座计时。默认 60（1 秒≈1 分钟），40 秒素材即可演示满 30 分钟的占座判定；设 1 按真实时长。
- **采样间隔 sample_interval**：默认每 1 秒取 1 帧（stride = fps），90 秒视频约 90 次推理、CPU 上 15 秒处理完。

### 实现要点

1. **推理串行锁**：YOLO 权重是进程单例，后台线程与 HTTP 请求共用一把 `INFERENCE_LOCK`，避免多线程同时 predict 争用模型
2. **状态机全复用**：视频每一帧走「检测 → judge_seats → SeatTracker.update」，防抖（连续 3 帧）与 30 分钟阈值逻辑和实时链路一字不差
3. **事件时长语义**：`duration_minutes` = 占座事件持续时间（end − start，与时间戳吻合）；`leave_minutes_total` = 该座位本次离座总时长（含阈值前缓冲）
4. **上传文件即用即删**：视频处理完（含出错/取消）自动从 `data/uploads/` 删除

### 验证记录（demo_scene.mp4，60 秒真实场景视频）

- 处理 60 帧 / 14.3 秒；C01、C02 在模拟第 29 分钟触发占座，事件 `21:28→21:54 占座 26 分钟（离座累计 50 分钟）`，与时间戳吻合
- `make_demo_video_from_image.py`：由真实机位图生成监控风格视频（亮度波动 + 抖动 + 时间戳），用于无摄像头环境演示

### 启动方式（重要：解决"闪退"）

命令行启动**必须先 cd 到项目目录**，否则 `app.main` 导入失败直接退出（表现为闪退）：

```
cd /d D:/seat-project
D:/miniconda3/envs/seat/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

推荐直接双击项目根目录的 **`start_server.bat`**：自动定位目录、检查端口占用、启动后自动打开浏览器、异常时窗口停留显示报错（不闪退）；配套 `stop_server.bat` 一键停止。
