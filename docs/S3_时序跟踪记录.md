# S3 时序跟踪模块记录

> 日期：2026-11-05　依赖：S2 的 seat_v1 权重 + 12 座 ROI

## 一、解决的问题

逐帧判定只能回答「此刻看到什么」，无法回答「这个座位被占了多久」。时序跟踪模块补上三层能力：

| 能力 | 机制 | 配置项 |
|---|---|---|
| 抗单帧误检 | 连续 N 帧状态一致才确认切换 | `empty_confirm_frames: 3` |
| 占座计时 | 「有物无人」累计满阈值才判定占座 | `object_leave_minutes: 30` |
| 时段豁免 | 午休、闭馆整理时段不累计 | `exempt_time.windows` |

## 二、代码结构

| 文件 | 职责 |
|---|---|
| `app/state_machine.py` | 状态机核心：防抖、累计有效时长、豁免判断、事件开闭 |
| `app/db.py` | SQLite 存储层：seats / observations / occupancy_events 三张表 |
| `scripts/track_stream.py` | 驱动：帧源 → 检测 → 判定 → 状态机 → 落库 → CSV 导出 |
| `tests/test_state_machine.py` | 13 条单元测试，不依赖模型与数据库 |

状态迁移：`空置 ⇄ 有人 ⇄ 有物无人`，只有「有物无人」状态累计离座时长。
事件结局：`RESOLVED`（人回来）、`CLEARED`（物品被清走）、`ONGOING`（流结束时仍在占座）、`INTERRUPTED`（异常中断）。

## 三、数据库表

```sql
seats             (id, name, x1, y1, x2, y2)                     -- 12 座静态信息
observations      (ts, seat_id, state, raw_state, person_count,
                   object_count, leave_minutes, violation)        -- 逐帧流水
occupancy_events  (seat_id, start_ts, end_ts, duration_minutes,
                   outcome, threshold_minutes)                    -- 占座事件
```

## 五、常用命令

```bash
# 图片序列（演示 30 分钟阈值最快的方式：单图循环 35 轮 = 虚拟 35 分钟）
python scripts/track_stream.py --source images --images data/video_demo/main_view.jpg --rounds 35

# 视频文件（每 30 帧采样一次）
python scripts/track_stream.py --source video --video data/video_demo/sim_cam1.mp4 --frame-step 30

# 摄像头/RTSP 实时（每帧代表 1 分钟仅用于课程演示）
python scripts/track_stream.py --source camera --camera 0

# 指定起始时间（配合豁免时段测试）
python scripts/track_stream.py --source images --images <图> --rounds 40 --start-time 2026-11-05T12:00 --minutes-per-frame 2
```

输出：`data/seat.db`（数据库）、`data/exports/occupancy_events_<时间>.csv`（事件清单）、`runs/track/<时间>/`（可选标注帧）。

## 六、已知限制与后续

1. **跨运行不续算**：每次启动独立计时。生产环境服务常驻运行不受影响；若要重启续算，应在启动时读取该座位最后一条 observation 的 `leave_minutes` 作为初始值
2. **单帧误检**：A02 的椅子背误检（conf 0.54）在静态单图循环中会被稳定确认，防抖只能过滤「偶发」误检；加入更多负样本重训可根除
3. **ROI 与机位强绑定**：换机位必须重新标定，否则判定全错
4. 下一步：FastAPI 接口 + 网页看板，把 `seat.db` 的状态与事件可视化
